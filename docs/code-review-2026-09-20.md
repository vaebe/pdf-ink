### Important

#### I-1 【本次变更引入】手写弹窗画布按「动画中的缩放盒子」计算分辨率

- **位置**：`src/components/SignaturePadDialog.vue:36-52`（`syncCanvasResolution`）配合 `:269` 面板新增的 `animate-panel-in`
- **机制**：`syncCanvasResolution()` 用 `canvas.getBoundingClientRect()` 取尺寸。本轮回合给面板加了 0.18s 入场动画（`panel-in`：`translateY(6px) scale(0.98)`），而 `createPad()` 在 `nextTick()` 后立刻执行——此刻动画正在 0.98 缩放态，`getBoundingClientRect()` 会把 transform 一并算进去，于是画布后备分辨率按**缩小 2% 的盒子**计算。
- **实测**（`review-probe.mjs` / `review-probe2.mjs`）：

  | 状态                                  | `canvas.width` | `offsetWidth × dpr` | 面板动画   |
  | ------------------------------------- | -------------- | ------------------- | ---------- |
  | 打开弹窗（当前实现）                  | **514**        | 524                 | `panel-in` |
  | 打开后触发一次窗口 resize 重新同步    | 524            | 524                 | `panel-in` |
  | `prefers-reduced-motion: reduce` 打开 | **524**        | 524                 | `none`     |

  最后一行是根因的判定实验：关掉动画，数值直接正确 → 偏差确实来自本次新增的入场动画。

- **影响**：画布覆盖范围比它所在的元素窄/矮约 8 CSS px，手写区最右、最下一小条落在画布之外，写在那里不会留下笔迹；同时笔迹分辨率比预期低 2%。说明：我尝试用「同一笔画的最右墨迹列」构造用户可见的裁切证据（`review-probe3.mjs` / `review-probe4.mjs`），两种状态都停在 504 列，**未能构造出可复现的视觉裁切**，因此这条按「尺寸不自洽」定性——数值不自洽本身已可证（514 ≠ 524），用户能否察觉取决于是否恰好写到边条。
- **建议修法**（任选，都是小改动）：
  1. 测量改用不受 transform 影响的布局尺寸：`canvas.offsetWidth` / `canvas.offsetHeight`；
  2. 或在面板 `animationend` 后再重新同步一次分辨率（复用现有 `resizeKeepingInk`）。

#### I-2 【既有缺陷，本次未引入】PDF 内链接点不动

- **位置**：`src/styles/pdfjs-text-layer.css:25`（`.pdf-text-layer` 缺 `z-index: 0`）
- **机制**：PDF.js 参考实现（`node_modules/pdfjs-dist/web/pdf_viewer.css` 的 `.textLayer`）给容器写了 `position:absolute; inset:0; z-index:0`。`z-index:0` 让容器成为层叠上下文，其内部 `z-index:1` 的透明文字 `<span>` 被关在容器内，后出现在 DOM 里的链接层才能压在上面。移植时丢掉了这条 `z-index`（容器为 `z-index:auto`），文字 span 的 `z-index:1` 就跑到了链接层之上——文字虽然透明，但仍会吞掉指针事件。
- **实测**（`review-probe.mjs` / `review-probe2.mjs`）：

  | 状态                                  | 链接区域中心 `elementFromPoint` | 命中 `<a>`？ | 真点击是否跳转                   |
  | ------------------------------------- | ------------------------------- | ------------ | -------------------------------- |
  | 当前实现                              | `span`（文字层）                | 否           | **否**（无新标签页、无外发请求） |
  | 页内注入 `.pdf-text-layer{z-index:0}` | `a`                             | 是           | **是**                           |

- **归因**：迁移前的 BEM 样式同样没有这条 `z-index`（见 `src-before-fix/style.css:440`），所以是既有缺陷，不是本次引入；但**本次审查是它第一次被证实**。附带一个验收盲区：A9 只断言「导出后 Link 注解仍在（pypdf 读回）」，从未验证页面上能否点。
- **建议修法**：在 `src/styles/pdfjs-text-layer.css` 的 `.pdf-text-layer` 补 `z-index: 0;`（该文件本就属 PDF.js 契约文件，放入正当），并给验收补一条「链接区域 `elementFromPoint` 命中 `<a>`」或「点击后触发跳转」的断言。

#### I-3 【既有缺陷，本次未修】切换态按钮 hover 时激活样式被基础 hover 规则盖掉

- **位置**：`src/style.css:173-183`（`.button--ghost` 的 `enabled:hover:` 与 `.button--toggled`）
- **机制**：`.button--ghost:enabled:hover` 特异性为 (0,3,0)，`.button--toggled` 只有 (0,1,0)，同一层内特异性高的胜出 → 激活态在鼠标悬停时被基础 hover 覆盖。
- **实测**（`review-probe8.mjs`，已打开 PDF 使按钮可用）：

  | 按钮状态      | 边框                           | 底色                                |
  | ------------- | ------------------------------ | ----------------------------------- |
  | 激活（静止）  | `rgb(47,111,237)` accent       | `rgba(47,111,237,0.12)` accent-soft |
  | 激活（hover） | `rgb(195,200,210)` line-strong | `rgb(247,248,250)` surface-muted    |

  即「适合宽度」被激活后，鼠标一移上去反而看不出是激活态。

- **归因**：旧 CSS 的 `.button--ghost:hover:not(:disabled)` 同样是 (0,3,0)，且旧模板用的也是 `class="button button--ghost" + :class="{ 'button--toggled': fitWidth }"` → 行为一致，非本次引入。
- **建议修法**：把修饰态的保护写进同层、特异性不低于基础 hover：`.button--toggled:enabled:hover { @apply border-accent bg-accent-soft; }`。

## 四、优点

- **令牌双层设计切中要害**：`:root` 原生变量管浅/深色开关，`@theme inline` 把令牌内联成 `var(--surface)`，因此深色模式零 `dark:` 变体、模板里没有任何主题分支——这是整套迁移里最省心的一个决定。
- **主动给 PDF.js 划出「不可工具类化」的红线**，并把原因写在文件头注释里（`src/styles/pdfjs-text-layer.css`），而不是让它散落在工具类中间。
- **三处「同属性双工具类」缺陷（激活态高亮、当前页缩略图、放置层 `pointer-events`）修得干净**：统一改成三元只输出一组类，而不是靠调顺序或加 `!important` 续命；并且是在真实浏览器里用计算样式抓出来的，构建与单测都抓不到。
- **验收脚本改用 `data-testid`** 代替视觉类名，把「下次重构样式不再静默破坏脚本」变成了结构性保证。
- 契约层（坐标换算 + 导出）有独立的数值回归（86 项）兜底，与样式重构解耦得很清楚。

### 修复 P2-3 时发现的上游根因（必须一并修）

`PdfPage.vue` 的 `IntersectionObserver` 原本写作 `{ root: null, rootMargin: "900px 0px" }`。
**`rootMargin` 只扩大 root 的矩形，而交叉矩形还要经过中间每个滚动祖先可视区的裁剪**——
root 为视口时，滚动容器自己的可视区把扩大出来的部分整块裁掉，900px 预渲染余量**实际等于 0**。

实测证据：第 13 页在视口中时，第 14 页 `top=1154`（落在扩大后的视口底边 1800 以内），
却 `canvas.width=1`、从未渲染。这条同时解释了 A11 原先为什么「一次只渲染 1 页」。

若只做「离屏即释放」而不修这一条，滚回已看过的页面就会重新经历一次渲染，**把内存修复变成白页回归**。
因此把 root 显式指向滚动容器（模板上新增 `data-scroll-root` 锚点）。改后同样位置第 12、13、14 页
都持有缓冲：进入视野前 900px 开始渲染、离开 900px 后才释放。

一处刻意保留：离屏释放**保留 `viewport` 与链接**。两者都很轻，而签名层要靠 `viewport` 把实例还原到
页面上；丢掉它，页面一离屏签名 DOM 就整体消失，会静默打破 A3-1 与 A4-1 的跨页实例计数。

### P2-4 的复现难点与处理

直接按「打开 A → 打开 B」执行**复现不出**——观察器的首次回调在实践中只比 DOM 更新晚
几毫秒，`getPage()` 还没来得及返回，stale 分支就已经被会话身份检查挡住。为把这条竞态
变成确定性复现，验收脚本在页面里替换 `IntersectionObserver`，给命中缩略图的回调**投递**
加 400ms 延迟（只延迟投递，不改变回调内容），让 stale 渲染有机会跑完。同一扰动下旧实现
稳定 8 项全空白、新实现稳定 0 项空白，区分力因此可证。

缩略图观察器本身另有 `rootMargin: "240px 0px"`（`root: null`）。因第七节已确认这类组合
可能被滚动容器可视区裁掉，本轮一并实测核查：初次加载时面板内 5 项全部已绘制，且紧邻
底部、落在 240px 余量内的第 6 项也已提前渲染——**余量在缩略图上确实生效**，不存在与
P2-3 同源的失效，故未改动。
