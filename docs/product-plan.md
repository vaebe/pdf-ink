# PDFInk 产品与实现方案

本文整理当前讨论中已确认的方向，以及建议方案和待确认事项，作为后续开发的依据；不代表相关功能已经实现。

## 1. 产品定位

- **产品名称**：PDFInk。
- **当前项目目录及包名**：`pdf-ink`，沿用现有项目命名。
- **中文描述**：PDF 手写签名工具。
- **产品标语**：保存常用签名，轻松签署 PDF。
- **核心目标**：打开 PDF，添加手写签名，下载处理后的 PDF，并支持保存多个签名以便重复使用。

这里的签名是写入 PDF 的可见手写笔迹，不提供证书数字签名、签署人身份认证或文件篡改验证能力。

## 2. 已确认的方向

1. 只针对 PDF，不扩展到 Word、图片等其他文档格式。
2. 支持手写签名，并保存多个签名。
3. 支持把签名放置到 PDF 上，并下载结果。
4. 采用开源技术方案，不选择商业 PDF SDK。
5. 先做网页应用，优先做好预览与签名体验；PWA 安装能力作为后续增强方向。

## 3. 建议的首版功能

以下细节是建议的实施范围，尚未逐项确认。

| 模块     | 建议功能                                           |
| -------- | -------------------------------------------------- |
| PDF 打开 | 选择本地 PDF，显示文件名与页数                     |
| PDF 预览 | 分页阅读、页面跳转、缩放、适合宽度、缩略图         |
| 新建签名 | 手写输入、清空重写、裁剪多余空白、透明背景保存     |
| 签名库   | 保存多个签名，展示预览，支持命名、重命名、删除     |
| 放置签名 | 选择签名后点击页面放置，支持重复使用和一页多个签名 |
| 调整签名 | 选中、拖动、等比缩放、删除                         |
| 编辑恢复 | 撤销和重做页面上的签名操作                         |
| 导出     | 将签名写入原 PDF，下载为新文件                     |

建议将“签名模板”和“页面签名实例”分开管理：

- 签名模板用于跨文档复用。
- 页面实例表示当前文档某一页上的签名及其位置、尺寸。
- 删除页面实例不删除模板。
- 建议删除模板时保留当前文档已放置的实例，避免编辑结果意外变化。

首版不纳入证书签名、合同流程、多人协同、PDF 正文编辑和桌面应用打包。

## 4. 用户流程与界面

### 主流程

1. 打开本地 PDF。
2. 从签名库选择签名，或手写创建新签名。
3. 在目标页面点击放置。
4. 调整签名位置与大小，按需继续添加。
5. 下载添加签名后的 PDF。

### 建议布局

- 顶部：文件名、页码、缩放、下载入口。
- 左侧：页面缩略图。
- 中间：PDF 阅读与签名编辑区域。
- 右侧：签名库和新建签名入口。

布局需根据目标设备调整；是否仅支持 PC 尚未确认。

## 5. 技术方案

### 现有项目基础

当前项目已声明 Vue、TypeScript 和 Vite+。本次仅整理文档，不新增依赖、不修改应用代码。

### 建议选型

| 职责           | 方案                           | 状态                     |
| -------------- | ------------------------------ | ------------------------ |
| 应用界面       | Vue + TypeScript               | 现有项目基础             |
| PDF 解析与预览 | PDF.js                         | 推荐，尚未集成           |
| 手写输入       | Canvas，可评估 signature_pad   | 候选，需确认版本及许可   |
| 页面签名交互   | 独立编辑层处理选择、拖动、缩放 | 建议方案                 |
| PDF 写入与导出 | 可评估 pdf-lib                 | 候选，需核实兼容性与许可 |
| 签名本地保存   | IndexedDB                      | 推荐，保存方式待确认     |
| 可安装与离线   | PWA                            | 后续增强，需定义离线范围 |

PDF.js 官方定位是 PDF 解析与渲染平台，采用 Apache 2.0 许可。参考：[项目介绍](https://mozilla.github.io/pdf.js/)、[官方阅读器示例](https://mozilla.github.io/pdf.js/web/viewer.html)。其他候选库尚未完成当前版本的选型核实。

### 处理流程

```text
本地 PDF → 读取原始字节 → PDF.js 预览
                            ↓
签名库 → 选择签名 → 页面编辑层 → 记录页码、位置和尺寸
                            ↓
                 在原 PDF 中写入签名 → 下载新文件
```

建议在浏览器本地完成处理，不上传 PDF 或签名。网站服务仅负责提供应用资源。此项仍需在开发时落实，不能仅凭架构描述宣称已经实现。

预览应结合页面渲染、文字层和链接等相关层，不只把 PDF 显示为图片。导出应在原 PDF 中加入签名，不将整份文档截图后重新拼接；原有内容能否完整保留需通过实际文件验证。

## 6. 数据与保存方式

### 建议数据结构

| 数据         | 内容                                             |
| ------------ | ------------------------------------------------ |
| 签名模板     | 唯一编号、名称、透明背景图片、原始宽高、创建时间 |
| 页面签名实例 | 实例编号、签名图片引用、页码、页面坐标、显示尺寸 |
| 当前文档     | 原始 PDF 字节、文件名、页面信息、签名实例集合    |

图片引用的生命周期应独立于模板删除操作，确保当前文档仍可正常导出。

### 本地保存建议

建议使用 IndexedDB 保存签名库，当前 PDF 和编辑状态先保留在当前会话，不默认保存历史文档。

本地签名仅供同一站点、同一浏览器环境使用；清除网站数据后可能丢失，不能自动跨设备同步。可考虑增加签名库导出与导入，作为备份和迁移方式，是否纳入首版待确认。

账号、云端存储和跨设备同步尚未获确认，不作为当前默认开发范围。

## 7. 体验与实现重点

### 坐标一致

采用统一的 PDF 页面坐标保存实例，通过页面变换处理缩放、旋转及裁剪区域。不要将屏幕像素直接作为持久坐标；导出位置必须与预览一致。

### 清晰与流畅

根据可见页面安排渲染，避免长文档同时渲染全部页面。拖动签名时优先更新编辑层，避免每次移动都重新渲染 PDF。实际文件规模和性能指标需结合目标设备确认。

### 文件兼容

加密文件、已有数字签名的文件和复杂表单需单独明确支持范围。修改已有数字签名的 PDF 可能影响其验证结果，不应默认当作普通文件无差别处理。

## 8. 分阶段实施建议

1. **阅读与导出基础**：打开 PDF、分页预览、坐标换算、将一个签名写入并下载。
2. **完整签名流程**：手写输入、多个签名保存、页面放置、调整和删除。
3. **体验完善**：缩略图、撤销重做、长文档渲染优化及兼容性处理。
4. **按需增强**：签名库备份、PWA 安装与离线能力。

这是开发顺序建议，不代表已授权实施全部功能或安装候选依赖。

## 9. 待确认事项

开发前按影响顺序确认：

1. 使用设备：仅 PC，还是同时支持手机、平板触控手写？
2. 签名保存：是否采用无账号的浏览器本地保存？
3. 首版是否包含签名库备份与恢复？
4. 是否需要上传已有签名图片，还是仅支持现场手写？
5. 加密 PDF 等特殊文件的支持范围。

## 10. 后续验收重点

以下是建议的验收场景，本次未执行：

- 保存多个签名，刷新后仍可选择和管理。
- 同一个签名能重复放置到不同页面。
- 删除页面实例不影响模板；模板删除行为符合约定。
- 缩放、页面旋转及不同页面尺寸下，预览与导出的位置、大小一致。
- 导出 PDF 可正常打开，签名清晰，并核实原有文字、链接等内容的保留情况。
- 取消编辑或导出为新文件时，不改写用户原文件。
- 若采用本地处理方案，核实 PDF 和签名没有被上传。

运行测试、启动应用或扩大检查范围，均按项目协作约定另行授权。
