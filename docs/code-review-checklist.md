# 代码审查速查清单

配套 `docs/code-review-guidelines.md`（判据来源）。本文件只做**勾选**，不重复解释；每条后面括号里是《标准》的对应条款。

---

## 一、提交前（作者）

### 1. 事前登记

- [ ] 本次变更是否触及**不可回退契约**（《标准》5.1 的 C-01～C-19）？**触及**时按 5.2 在 PR 中写明：契约怎么变、谁补偿、补哪条断言 + 区分力对照；**未触及**时在 PR 中写明「未触及契约」。

### 2. 五道门禁（逐条记录命令与实测结果，不要只写「通过」）

- [ ] `vp check <改动路径>` —— 0 error / 0 warning / 0 type error（3.1-1）
- [ ] `vp run build` —— 含 `vue-tsc -b`，无 TS 错误（3.1-2）
- [ ] `vp test --project geometry` —— 全部通过（3.1-3）
- [ ] `git diff --check` —— 无输出；**新增文件单独扫一遍**空白/末尾空行/CRLF（3.1-4、3.2-2）
- [ ] 浏览器验收 `vp test --project acceptance` —— 全部通过，连续两轮结论一致；本次新增的可验收行为**已补断言**（3.1-5）

### 3. 门禁执行纪律

- [ ] 没有跑全仓 `vp check --fix`（3.2-1）
- [ ] 跑验收期间未写入项目目录下任何文件（3.2-4）
- [ ] 门禁 3 用的是 Vite+/pnpm 托管的 Node 24.x（3.2-5）
- [ ] 提交路径集合自洽：`pnpm-lock.yaml` 随 `package.json`；`scripts/` 未被漏掉（3.2-6）
- [ ] 提交后确认 `git diff HEAD` 为空、`git stash list` 为空（钩子回写已进提交，3.2-3）

### 4. 自查（六类高风险，对应《标准》4.1）

- [ ] **R1 异步竞态**：每个 `await` 之后写回共享状态前核对了身份；闸门在进入第一个 `await` **之前**置位；闸门**复位**也有断言
- [ ] **R1 复现**：竞态类修复附了确定性复现手段（注入回调投递延迟），不是只跑 happy path
- [ ] **R2 资源**：释放的是重资源、保留的是还原依据（`viewport`/links）；无只增不减的计数器；所有失败出口都有清理
- [ ] **R3 契约**：同一语义只有一条路径（如 clamp 同源）；无「静态类 + 条件类写同一属性」
- [ ] **R4 生命周期**：`watch`/`onMounted` 确实会执行（未被父级 `:key` 重挂载架空）；`rootMargin` 用量具确认生效
- [ ] **R5 验证**：新增可验收元素补了 `data-testid`；断言不恒真；断言有区分力对照
- [ ] **R6 隐私**：无远端请求/引用；原始文件不改写；确认走应用内 dialog

### 5. 通用自查（《标准》4.2）

- [ ] 边界条件想过一遍：空文档、单页、损坏文件、极端视口、四种旋转 + 非零 CropBox
- [ ] 错误路径有提示且不破坏既有会话
- [ ] 无 `v-html`/`innerHTML` 渲染用户或 PDF 派生内容
- [ ] 无死代码；无超出本次范围的改动（含格式化范围，A-4）
- [ ] 可访问性：键盘可达、焦点管理、对比度 ≥ 4.5:1（正文）、`prefers-reduced-motion`
- [ ] 变更 ≤ 400 行有效代码，且**只做一件事**

## 二、审查中（评审者）

### 1. 前置

- [ ] 基准明确：以 HEAD（或指定提交）为基准，**覆盖未提交改动及新增文件**
- [ ] 作者未自审（若为「自审（隔轮）」已注明，且未豁免任何机器门禁）（2.1）
- [ ] 门禁结果已核对（不是只看作者的文字结论）

### 2. 逐项核对

- [ ] 事前登记的契约影响与实际 diff 一致；触及契约时断言与对照齐备（5.2）
- [ ] 按 R1→R6 顺序过一遍**实际代码**，重点看 `await` 之后、清理路径、名称与生命周期
- [ ] 对每个可疑点**实际验证**（写探针/跑一次），不凭阅读下结论（2.2-④）
- [ ] 检查是否有「过修」：只合闸门不复位、只加限制不补偿
- [ ] 检查是否有越界改动（A-4）：不属于本变更的既有文件被格式化/清理
- [ ] 核对第 6 节七个历史模式（A-1 晚一行 / A-2 旧节点写新数据 / A-3 只约束一侧 / A-4 越界纠正 / A-5 恒真断言 / A-6 焦点掉到 body / A-7 静态观感代替实测）

### 3. 判定与产出

- [ ] 逐条定级 P0—P3，**每条附触发条件或标注「未实证」**（1.1、2.2）
- [ ] 未使用被禁止的降级理由（「验收没覆盖」「看着没问题」「现实中很少见」）（1.2）
- [ ] 结论为 `APPROVE` / `APPROVE_WITH_COMMENTS` / `REQUEST_CHANGES`，与问题清单自洽（1.3）
- [ ] 意见**一次列全**，不挤牙膏（2.3）
- [ ] 审查记录按《标准》2.4 格式产出，归档到 `docs/code-review-<日期>.md`
- [ ] 记录了「做得好的部分」（7.2）

---

## 三、合并前（合并者）

- [ ] 五道门禁全绿，且失败项只可能是 P3（3.3）
- [ ] 无未修复的 P0/P1
- [ ] P2 已全部修复，或已登记为带触发条件与 owner 的 issue（1.3）
- [ ] 存量非合规文件已在本 PR 中列明（「已知存量、未处理、原因」），未被悄悄扩大格式化范围（3.3、A-4）
- [ ] 契约变更已回写《标准》5.1 与 README（5.2）
- [ ] 审查记录已归档
- [ ] 同一问题未超过三轮往返；若超过已转线下对齐（2.3）

## 四、命令块（可直接复制）

```bash
# 1) 格式 / Lint / 类型（按改动范围，不要跑全仓 --fix）
vp check src vite.config.ts README.md

# 2) 构建（含 vue-tsc -b）
vp run build

# 3) 数值契约（必须用 Vite+/pnpm 托管的 Node 24.x）
vp test --project geometry

# 4) 空白与差异卫生（注意：不覆盖未跟踪文件）
git diff --check
git status --short

# 5) 浏览器验收（⚠️ 执行期间不要写项目目录下的任何文件）
vp run dev --port 5199 --strictPort # 另一个终端；同步资源并固定端口
vp test --project acceptance # 1 个用例、59 项断言；产物落在仓库外

# 提交后确认钩子回写已进提交
git diff HEAD --stat
git stash list
```
