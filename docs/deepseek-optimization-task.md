## 3. 本轮实施项

### A. 统一共享编辑器的派生状态与初始化生命周期

相关文件：

- `src/composables/useSignatureEditor.ts`
- `src/App.vue`
- 调用链核对：`src/components/SignatureLibrary.vue`、`src/components/SignatureOverlay.vue`

当前情况：编辑器基础状态定义在模块级，但每次调用 `useSignatureEditor()` 都会创建文档重置 watcher、按页分组 computed 和选中实例 computed。App、签名库及每页的覆盖层都调用它，导致派生计算随消费者重复创建。

实施要求：

1. 让按页分组、选中实例及其他共享派生状态只创建一份，消费者继续获取同一份状态和操作能力。
2. 文档切换的重置监听由唯一的应用级入口安装，并随该入口卸载清理。不要让任意页面组件的挂载或卸载决定全局编辑器生命周期。
3. 保留现有重置语义：切换成功后清空实例、选择、放置模式、历史记录，并释放旧预览 URL。
4. 不用“模块布尔值 + 任意首个消费者 watcher”实现一次初始化，避免首个消费者卸载后监听消失却无法重建。
5. 不扩展为多文档编辑器，也不新增通用状态框架。

静态验收：逐个核对上述调用方，确认页面数量不会增加全局重置监听和共享分组计算的数量；会话切换仍有唯一、明确的重置入口。

### B. 正确记录最近一次导出对应的编辑状态

相关文件：`src/App.vue`，必要时配合 `useSignatureEditor.ts`。

当前情况：`hasUnsavedEdits` 仅判断实例数量大于零。成功下载后再次打开文件，仍提示当前签名“尚未导出”。

实施要求：

1. 在新会话建立时，以空实例列表作为初始基准。
2. 使用最近一次成功生成并发起下载的实例快照作为导出基准，与当前实例状态比较。
3. 快照比较涵盖实例顺序、实例 id、assetId、pageIndex 和六个矩阵数值。比较实现保持简单，不引入通用深比较依赖。
4. 导出失败时不更新基准；导出期间继续编辑时，成功后只能记录本次实际导出的快照，不能把完成时的实时状态标为已导出。
5. 如果导出期间已切换文档，旧文档的导出完成不能覆盖新会话的基准。用会话身份核对归属。
6. 撤销或重做到与基准相同的状态时，应恢复为没有未导出变更。
7. 检查放弃编辑弹窗的说明：导出后删除所有实例也可能形成与基准不同的状态，不要显示“0 个签名尚未导出”这类失真的说明。改为准确描述“存在尚未导出的修改”，保留原有确认行为和原文件不受影响的说明。
8. 浏览器触发下载不等于能确认用户已保存到磁盘，不新增这种成功保证。

静态验收场景：初次打开、添加实例、成功导出、导出失败、导出期间继续编辑、导出期间切换文件、删除全部实例、撤销与重做。逐项沿状态写入路径检查，不运行这些场景。

### C. 仅在新会话成功建立后重置阅读状态

相关文件：`src/App.vue`、`src/composables/usePdfDocument.ts`；核对 `src/components/PdfViewer.vue`。

当前情况：`handleOpenFile()` 在 `openFile()` 成功前就把页码归零、开启适合宽度。加载失败或取消数字签名确认时，旧文档保留，但阅读状态已经被改变。

实施要求：

1. 将页码归零和适合宽度重置移到成功切换会话的路径。
2. 优先利用现有 session/documentId 成功切换信号，不为了这一点引入新的事件系统。
3. 保持成功打开新文件后从第一页、适合宽度开始。
4. 取消或失败时保留旧文档的页码、缩放模式和滚动位置。
5. 不误伤 `PdfViewer` 现有 key 重建和缩放后定位逻辑。

静态验收：核对取消放弃确认、取消数字签名确认、读取失败、成功切换、过期加载结果这五条路径。

### D. 补齐 pending PDF 加载任务的清理

相关文件：`src/composables/usePdfDocument.ts`。

当前情况：`loadingTask.promise` 失败会销毁任务，但它成功之后，`readPageGeometries()` 读取某页失败时没有清理。此时任务尚未交给 session，也不会由旧会话的销毁逻辑接管。

实施要求：

1. 明确任务所有权：新任务处于 pending 阶段时由加载流程管理，成功交接后由 session 管理。
2. pending 阶段发生异常、请求过期或退出时，销毁对应任务。
3. 交接完成后不能在兜底清理中销毁当前会话任务。
4. 保留旧会话延后销毁的行为，避免旧页面尚在使用时提前销毁它。
5. 保留原始错误供现有错误提示处理，不让清理错误替换主要错误。
6. 避免分支重复销毁，优先以局部的所有权标记和 `try/finally` 收拢，不新增任务管理框架。

静态验收：列出任务创建、加载失败、页面几何读取失败、请求过期、成功交接、旧会话销毁的所有出口，核对每个任务的责任归属。

### E. 让数字签名提示与检测能力一致

相关文件：

- `src/lib/pdfExport.ts`
- `src/composables/usePdfDocument.ts`
- `src/App.vue`
- `src/types/pdf.ts`
- `README.md` 中对应的当前行为说明

当前情况：`inspectDigitalSignatures()` 检查签名字段是否存在 `/V`，并未进行证书或密码学验签，但提示称其为“有效的数字签名”。

实施要求：

1. 将“有效的数字签名”调整为“检测到数字签名”等符合当前检测能力的表达。
2. 类型和函数注释明确：这是签名字段及签名值的存在性检测，不证明真实性或有效性。
3. 保持已检测到签名时的确认流程和导出风险说明。
4. 不新增验签能力，不改变当前检测算法，不顺手调整异常降级策略。
5. 只同步 README 中对应的当前说明；历史审核、实施记录不批量改写。

静态验收：搜索上述指定文件中的相关文案和注释，确认不再把字段存在性描述为有效性验证。
