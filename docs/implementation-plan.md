# PDFInk 执行方案与验收约定

## 1. 交接状态

- 产品背景：`docs/product-plan.md`。
- 执行者：用户指定的 DeepSeek4.1。
- 最终验收：由当前协作助手在实现完成后，基于实际代码和验证证据进行。
- 工作分支：`develop`，由 `main` 的 `c8e02baab7a767fe9b319052cf8fb6093a70179c` 创建。
- 当前基础：Vue + TypeScript + Vite+ 初始化模板，尚未实现 PDF 功能。
- 本文是执行计划，不是完成报告；创建分支不包含提交、推送或安装依赖。

## 2. 开始实现前的范围门槛

已确认：开源网页工具，仅处理 PDF，支持手写签名、保存多个签名、放置后下载。

以下是待确认的首版建议，不得当作用户已经同意的业务规则：

- PC 优先；手机和平板专门适配暂缓。
- 无账号，签名保存在当前站点的 IndexedDB；PDF 和编辑状态仅在会话中保存。
- 仅现场手写，不支持导入签名图片。
- 签名库备份、PWA、云端同步、加密 PDF 暂缓。
- 已有证书数字签名的 PDF：建议识别后拒绝编辑，具体识别方式在 S0 核实；不能仅凭页面上是否有签名图片判断。处理边界仍需明确决定。

执行者应先读取用户后续确认；缺少决定时只说明具体阻塞，不自行补全，也不重复询问已确认内容。新增依赖须有明确授权；建议一次确认 `pdfjs-dist`、`pdf-lib`、`signature_pad` 三个依赖后实施，不引入其他框架。

## 3. 技术约定

### 3.1 工程与范围

- 保留 Vue、TypeScript、Vite+，不迁移工具链。不增加路由、状态管理库、后端或 UI 框架。
- 阅读根目录 `AGENTS.md` 和当前工作区差异。仅改动本方案直接涉及的文件，保留他人改动。
- 使用 `vp` 管理项目。依赖版本以实际兼容性核实结果为准，锁定在 lockfile，并记录版本与许可证；不能凭本文猜测 API。
- 原有 `vite.config.ts` 开启了类型检查，不能关闭规则掩盖错误。

### 3.3 数据契约

- `SignatureTemplate`：`id`、`name`、透明 PNG `blob`、`pixelWidth`、`pixelHeight`、`createdAt`。名称去除首尾空格且不可为空；不以名称作为主键。
- `SignatureAsset`：当前会话持有的不可变图片数据及尺寸，通过 `assetId` 引用。首次使用模板时放入会话，不能只在实例里保存模板编号。
- `SignaturePlacement`：`id`、`assetId`、从 0 开始的 `pageIndex`、图片单位正方形到 PDF 用户空间的六参数仿射矩阵。矩阵同时保存位置、尺寸和方向。
- `DocumentSession`：文件名、独立保存的 `originalBytes`、PDF.js 对象、页面几何信息、会话图片及实例列表。
- 工具栏页码从 1 开始；仅 UI 边界转换，内部统一从 0 开始。
- 模板删除不影响会话图片和撤销记录；签名库操作不纳入页面编辑的撤销栈。

### 3.4 坐标与导出契约

1. 指针位置先转为页面 viewport 的 CSS 坐标，扣除页面内容区域偏移；边框、滚动和 DPR 不可混为一套坐标。
2. 使用 PDF.js 当前页面 viewport 的逆变换，将图片的左下、右下、左上三个角转换为 PDF 用户空间点 `P0`、`P1`、`P2`。
3. 存储矩阵 `[P1.x-P0.x, P1.y-P0.y, P2.x-P0.x, P2.y-P0.y, P0.x, P0.y]`，约定图片单位空间原点为左下角。
4. 预览通过当前 viewport 正向变换还原图片位置。页面内置旋转、非零 CropBox 原点必须由变换处理，禁止只用 `pageHeight - y`。DOM 图片原点为左上角，不能直接套用左下原点的 PDF 矩阵作为 CSS transform；先将对应的左上、右上、左下三个点转换为 viewport 点，再构建 DOM 变换，或在本方案无自由旋转的前提下还原页面矩形。
5. PDF 写入保持原页面旋转与页面框。对矩阵 `[a,b,c,d,e,f]`，使用 `drawImage` 的 `x=e`、`y=f`、`width=Math.hypot(a,b)`、`height=Math.hypot(c,d)`、`rotate=degrees(Math.atan2(b,a)*180/Math.PI)`；该分解适用于本方案无镜像、无斜切的等比编辑。不能对旋转重复补偿。此契约已与官方绘制变换顺序对照，但仍需实际 PDF 验证。
6. 首版用户不能自由旋转签名，也不提供页面旋转编辑；必须正确显示和导出原文件已有的 0/90/180/270 度页面旋转。
7. 页面拖动和缩放限制在可见页面区域，默认保持签名长宽比；缩放页面只改变预览，不改实例的 PDF 坐标。

若矩阵绘制所需 API 与安装版本不匹配，先查该版本声明和官方源码，在基础导出阶段解决，不推迟到 UI 完成后处理。

### 3.5 生命周期和异步处理

- PDF.js 可能将传入的 TypedArray 转移给 worker。保留导出专用原始字节，传给预览器的是独立副本。
- PDF worker 与主库版本一致，本地提供所需字体、CMap、WASM 等资源；依据安装版本配置，不从未经确认的 CDN 加载。
- 替换采用两阶段切换：新文件先作为 pending 加载，成功且仍是最新请求后才切换会话、取消旧渲染并销毁旧文档。新文件加载失败保留旧会话；过时 pending 请求单独取消并销毁，不能覆盖当前会话。
- 同一 canvas 的旧渲染先取消并结束，再启动新渲染；正常取消不展示为业务错误。
- 仅渲染可见页及有限相邻页，缩略图也按需调度；拖动签名只更新编辑层。
- PNG URL、下载 URL 和事件监听器在相应生命周期释放。会话结束前，不释放仍被实例或撤销记录使用的图片。
- IndexedDB 以事务完成作为保存成功；失败时保留手写内容并明确提示，不能显示虚假的成功状态。

## 4. 分阶段执行任务

按顺序完成，每阶段报告实际完成项、修改文件和检查结果。上一阶段的关键契约未解决时，不靠补 UI 跳过问题。

### S0：确认范围和依赖

产出：记录范围确认、依赖版本/许可、worker 与本地资源配置办法。获得新增依赖授权后使用 `vp add`，不手改依赖版本来绕过工具链。

完成条件：执行者能说明首版边界、依赖来源及导出坐标实现方式。影响当前阶段实现的范围已有明确决定，未决项不进入实现。损坏文件归入加载失败路径，无需额外增加修复功能。

### S1：完成最小预览与导出路径

涉及：PDF 类型、文档加载、页面组件、坐标模块、导出模块。

- 打开 PDF，显示第一页及页数；保留原始字节。
- 接入匹配版本 worker，明确 PDF 加载和导出失败状态。
- 使用临时开发签名图片贯通“坐标 → 页面显示 → 写入 → 输出字节”，交付正式功能前删除临时入口。
- 处理页面原始旋转和 CropBox；本阶段先解决几何，不制作完整工具栏。

完成条件：代码中预览与导出共用明确的几何契约；如果尚未授权运行验证，记录“几何一致性未运行验证”，不能标记为验收通过。

### S2：手写签名与本地签名库

涉及：签名类型、存储模块、签名库、手写弹窗。

- 支持鼠标手写，适配高像素密度；只在画布内阻止默认指针行为。
- 空白签名不允许保存；透明 PNG 裁剪到笔迹边界并留少量边距。
- 保存名称和图片，关闭弹窗后在库中显示；支持重命名与删除。
- 再次加载签名库；明确持久化失败和空列表状态。

完成条件：所有数据库调用可追溯，保存成功以事务完成为准；无账号、无远程文件上传逻辑。

### S3：页面放置与编辑

涉及：编辑 composable、页面覆盖层、签名库联动。

- 选择模板后进入放置状态，点击页面添加一份实例；保持模板选中以供重复放置，Esc 退出。
- 点击已有实例只选中，不额外添加；拖动、等比缩放、删除。
- 一次拖动/缩放结束仅写入一条撤销记录；撤销后进行新编辑清空重做栈。
- 文本输入获得焦点时，删除和撤销快捷键不能误操作页面签名。
- 删除模板不破坏当前页面实例、导出或撤销。

完成条件：实例只依赖会话图片；所有页面编辑通过一致的状态入口，不直接在多个组件修改共享数组。

### S4：阅读体验和正式下载

涉及：工具栏、阅读容器、缩略图、样式、导出联动。

- 多页连续阅读、缩略图定位、页码跳转、缩放、自适应宽度。
- 保留文字选择与基础链接交互；放置模式外不让透明编辑层吞掉整页点击。
- 导出所有页面实例；同一图片按资源复用，避免每个实例重复嵌入。
- 从原始 PDF 重新导出，不把上次输出作为输入，避免连续下载导致签名叠加。
- 导出期间显示状态并防止重复触发；使用导出开始时的编辑快照，失败后可以重试。
- 输出文件名建议为原文件名加 `-signed.pdf`，不写回源文件。
- 替换有未导出编辑的文档时提示将清空当前编辑；新文件加载失败时保留旧会话。

完成条件：正式入口闭环，无临时图片、假下载或仅生成页面截图的实现。

### S5：交接与验收准备

- 更新 README 的产品说明、启动方式、当前支持范围与本地存储说明。
- 移除被替换模板直接遗留的无用引用，避免无关清理。
- 填写 `docs/implementation-report.md`：基准提交、阶段状态、改动文件、依赖、实际命令与退出结果、未验证项、已知问题。
- 不自行提交、合并或推送；用户另行要求时按授权范围处理。

## 5. 检查与运行验证边界

当前计划阶段只检查文档差异，不安装依赖、不启动应用、不运行测试。

实现阶段可以对改动文件执行 `git diff --check`。新增未跟踪文件需单独检查，不能以普通 diff 没有输出断言其通过。

`vp check --help` 已确认支持 `[PATHS]`。如执行 `vp check <本次文件列表>`，不能加 `--fix` 进行未经要求的批量修复；当前类型检查配置可能读取项目级类型依赖，需先核实实际范围，超出授权则说明并确认。不要默认执行全仓 `vp check` 或 `vp test`。

完整构建命令为 `vp run build`，对应 `vue-tsc -b && vp build`。其范围覆盖项目，需获得相应授权后执行；构建通过不等于功能通过。

下表供最终验收使用，运行时验证须在授权后进行；“最后由助手验收”是责任约定，本文不冒充已经运行测试。

## 8. 技术资料

- [PDF.js API](https://mozilla.github.io/pdf.js/api/draft/api.js.html)：TypedArray 所有权、加载资源和生命周期；开发时以锁定版本为准。
- [pdf-lib PDFPage API](https://pdf-lib.js.org/docs/api/classes/pdfpage)：图片绘制、页面框和旋转接口。
- [PDF.js PageViewport 源码](https://github.com/mozilla/pdf.js/blob/master/src/display/page_viewport.js)：页面正向和逆向坐标转换。
- [pdf-lib 绘制操作源码](https://github.com/Hopding/pdf-lib/blob/master/src/api/operations.ts)：图片平移、旋转、缩放的执行顺序。
- [signature_pad 官方仓库](https://github.com/szimek/signature_pad)：手写输入、空白判断和 PNG 输出。
- 项目本地 Vite+ 文档：`node_modules/vite-plus/docs/guide/check.md`、`install.md`。
